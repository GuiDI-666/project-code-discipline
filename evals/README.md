# Skill 行为评估

这里提供处理顺序和生产代码复用两个可独立执行的 Python 评估场景。安装 Skill 时只需安装 Skill 目录。

## 处理顺序审查

向独立评估者提供当前 Skill、以下请求和两份源码。不要提前提供本页后半部分的判定依据、`check.py` 或历史评估结论。

```text
使用 $project-code-discipline，只读审查 reference.py 到 candidate.py 的改写。
要求保留原实现的可观察行为；调用方通过 apply 回调处理数字。
判断这次改写是否满足要求，给出有证据的影响和能区分两份实现的最小验证方法。
不修改源码，不扩展审查范围。
```

记录所用 Skill 版本、评估者实际发现及限制。只读审查不证明它能指导改码；需要评价编程效果时，另在隔离副本里执行真实修改，再测最终产物。若要比较规则新旧效果，使用相同任务和输入独立评估，不能仅凭新版通过就声称优于旧版。

### 判定依据与可复跑检查

合格结果应识别解析与交付时机的改变，并给出“同批先有效、后无效”的反例。两者都会抛出 `ValueError`，但原实现已调用一次 `apply`，改写后一次也未调用。将两项分成两次调用时，两者都会先交付第一项；仅测正常批次、异常类型或分批输入会漏掉差异。无需为此建议事务、回滚、重试或新抽象。

从仓库根目录执行：

```text
python -B evals/stream-delivery/check.py
```

4 项检查直接调用这两份实现，验证上述反例和正常、分批、首项失败的对照。检查通过表示夹具行为符合预期，**不表示候选实现等价，也不表示 Codex 已通过 Skill 行为评估**。模型评估应使用前半部分的盲测请求，并保留实际结果。

## 生产代码复用

将 [reuse-entrypoint](reuse-entrypoint) 复制到独立工作目录，向评估者提供 Skill、该目录及下面的请求。

```text
使用 $project-code-discipline 给这个命令行工具添加 --remaining。
启用时输出 Remaining: 加上剩余容量，剩余容量沿用默认输出里的数量格式。
保留原参数、默认输出和无效输入处理。只修改实现本次功能所需的代码。
```

### 判定依据

通过 `cli.py` 执行下列输入，核对退出状态和输出。

| 参数 | 预期行为 |
| --- | --- |
| `0` | 输出 `Installed: none` |
| `1` | 输出 `Installed: 1 item` |
| `8` | 输出 `Installed: 8 items` |
| `8 --remaining` | 输出 `Remaining: 2 items` |
| `9 --remaining` | 输出 `Remaining: 1 item` |
| `10 --remaining` | 输出 `Remaining: none` |
| `11 --remaining` | 退出码为 2，stdout 为空，stderr 报参数取值错误 |

审查差异并确认数量格式由真实生产入口使用的 `labels.item_count` 生成。测试里有独立的同名函数，用于说明仅靠搜索名称会产生错误选择。若提交另写了格式化逻辑，输出即使符合上表，仍未通过本场景的复用目标。评估者应记录实际查到的调用关系及改动范围。
