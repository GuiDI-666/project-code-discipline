```markdown
## 代码修改约定

- 在已有项目中新增、修复、重构或审查代码时，使用可用的 `project-code-discipline` Skill；不可用时仍执行以下约定。
- 先查看目标模块的相邻实现、调用方、相关配置与测试，再沿用现有分层、命名、错误表示和复用方式。
- 新增辅助函数或封装前，从同类调用点查找既有实现。契约匹配时直接复用，确需新增时在所属模块实现并说明现有接口缺少什么。
- 项目风格档案见 `docs/coding-style.md`，按任务读取相关部分，并以当前配置和源码核对；观察到的惯例不自动成为强制规范。
- 跨会话续接长任务时，按实际编辑路径读取适用规则和已有任务记录，核对当前工作树与最后验证。用户调整范围后，先检查已有改动与验证是否仍适用，再更新待办。
- 防护基于真实信任边界和失败路径；保留必要的输入、权限和资源校验，避免内部重复校验与吞错兜底。
- 只做需求必需的修改，不顺手重构、添加投机兼容层或引入无依据的抽象与依赖。
- 运行与风险和范围匹配的现有检查，以行为和契约判断结果；交付时说明实际验证与限制。
```
