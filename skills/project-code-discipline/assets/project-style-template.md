# 项目代码风格档案模板

使用方式：只保留目标项目能够证实且对后续工作有价值的内容。替换提示文字，不把此模板原样当成项目事实。普通代码修改不要求创建档案。

## 范围与证据

- 适用目录或模块：填写实际范围。
- 核对日期与版本：记录真实日期及可获得的 Git 提交；存在未提交改动则注明。
- 显式规范：列出适用 AGENTS、格式/类型/检查配置和维护文档。
- 代表实现：填写文件路径、符号及其说明的惯例；行号可辅助定位，不能代替符号。
- 冲突与未知：记录尚无足够证据的部分，不补猜测。

## 影响本次工作的分析结论（按需）

| 判断 | 代码符号或配置依据 | 条件与适用范围 | 证据状态 | 对本次工作的影响 |
| --- | --- | --- | --- | --- |
| 填写可核对的判断 | 实际路径、符号或配置项 | 不遗漏启用条件 | 源码确认 / 运行验证 / 推断 / 待核实 | 需要沿用、调整或继续调查的决定 |

只保留影响任务的关键判断。可按需写出一条功能调用链和关键状态归属；不复制所有函数，不把待核实项写成既定架构。用户仅要求风格时可删除本节。

## 当前约定

| 主题 | 约定 | 类型 | 证据及适用范围 |
| --- | --- | --- | --- |
| 命名与格式 | 从实际项目填写 | 明确规范 / 观察惯例 / 建议 | 配置或实现位置 |
| 分层与复用 | 同上 | 同上 | 同上 |
| 类型与输入校验 | 同上 | 同上 | 同上 |
| 错误、日志与降级 | 同上 | 同上 | 同上 |
| 异步、事务与资源释放 | 同上 | 同上 | 同上 |
| 测试与检查 | 同上 | 同上 | 同上 |
| 配置文件写法 | 按文件记录键名、层级、缩进、引号、注释和列表习惯 | 观察惯例 | 实际配置样本 |
| 配置解析契约 | 相关键路径、类型、必填、缺省来源与生效阶段 | 源码确认 / 运行验证 | 加载器与消费点 |

删除不适用的行，补充当前项目真正需要的主题。建议尚未采纳前不作为硬性约束。

## 符号与使用契约（需要复原或约束既有定义时填写）

| 符号 | 原声明位置 | 原定义位置 | 完整签名或字段契约 | 调用/使用证据 | 条件与允许差异 |
| --- | --- | --- | --- | --- | --- |
| 填实际符号 | 路径、符号或范围 | 头文件内联也如实填写 | 保留类型拼写、顺序、默认值与限定符 | 调用文件、参数来源、资源生命周期 | 未授权的差异不默许 |

结构定义较大时指向已核对的完整摘录，不在表格中只列几个熟悉字段。排版样本与契约分开保存，避免把类型变更当成格式优化。不需要复原时删除本节。

关键使用链按需补充：`来源字段与类型 → 转换 → 局部变量 → 调用实参 → 接收参数 → 分发/读写 → 释放位置`。具体记录 case 形式、指针/引用和长度含义，不能只写“通过消息分发处理”。

跨模块迁移按需补充两端的构建归属、启用条件与阶段、资源所有者、处理/交付顺序、失败后状态及验证覆盖；不要仅用同名文件配对。允许调整的维度和仍须保持的行为分别记清。

响应或输出构造另记：`缓冲区 → 游标初始化 → 辅助函数签名 → 实际长度计算 → 封装/发送接口 → 返回与释放`。注明每层职责与失败语义，不把能产生相似输出的新函数当成相同使用风格。

## 可复用入口与验证

记录已确认的工具函数、组件、错误类型、领域服务和测试夹具的职责及位置。列出从真实配置核实的检查命令、执行目录、前置条件及已知限制；不要猜测构建命令。

## 维护

仅在架构、配置或惯例发生实质变化时更新。使用前核对涉及部分是否仍与代码一致。记录重要例外和原因，不复制整个仓库结构、不记录密钥或业务敏感样本。
